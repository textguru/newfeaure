## 4. 기능적 요구사항 (Functional Requirements)

### 4.1 지사별 시행종목 조회

#### REQ-001: 시험정보 선택
- **우선순위**: P0

**1. 요구사항 설명**
시스템은 사용자가 조회 조건을 입력하기 전에 기존에 등록된 시험정보 목록을 제공하여 사용자가 시험정보를 선택할 수 있어야 한다.

**2. 상세 로직 및 규칙**
- 규칙 1: 사용자가 조회 조건 영역에서 지사를 먼저 선택한 뒤 시험선택 버튼을 클릭하면, 해당 지사에서 시행되는 시험정보 목록을 팝업 형태로 표시한다.
- 규칙 2: 팝업에 표시되는 시험정보 목록은 선택된 지사에 해당하는 데이터만 필터링하여 표시한다.
- 규칙 3: 시험정보는 시험명, 시험일자, 시행종목 정보를 포함하여 표시한다.
- 예외 처리 1: 등록된 시험정보가 없을 경우 "조회된 시험정보가 없습니다." 안내 메시지를 표시한다.

**3. 검증 기준 (Acceptance Criteria)**

- **검증 기준 1**
    - **Given**: 시스템에 유효한 시험정보가 1건 이상 등록되어 있고, 사용자가 조회 조건 영역에서 지사를 선택한 상태이다.
    - **When**: 사용자가 시험선택 버튼을 클릭한다.
    - **Then**: 선택된 지사에 해당하는 시험정보 목록이 팝업으로 표시된다.

- **검증 기준 2**
    - **Given**: 시험정보 팝업이 표시된 상태이다.
    - **When**: 사용자가 팝업에서 특정 시험정보를 선택한다.
    - **Then**: 선택된 시험정보에 연관된 시험일자가 조회 조건 영역에 자동으로 세팅된다.

- **검증 기준 3**
    - **Given**: 시스템에 등록된 시험정보가 없다.
    - **When**: 사용자가 시험정보 선택을 시도한다.
    - **Then**: "조회된 시험정보가 없습니다." 안내 메시지가 표시된다.

**4. 데이터 요구사항**
- 입력 데이터: 지사 (지사별 조회 기준)
- 출력 데이터: 시험정보 목록 (시험ID, 시험명, 시험일자, 시행종목 정보)

---

#### REQ-002: 조회 조건 설정 (지사 및 시험일자)
- **우선순위**: P0

**1. 요구사항 설명**
시스템은 REQ-001에서 선택된 시험정보를 기반으로, 지사 및 시험일자를 조회 조건으로 자동 세팅하며 사용자가 조건을 변경·확정할 수 있어야 한다.

**2. 상세 로직 및 규칙**
- 규칙 1: 사용자가 조회 조건 영역에서 지사를 선택하면, 시험선택 버튼이 활성화된다.
- 규칙 2: 사용자가 필터링된 시험정보 팝업에서 특정 시험정보를 선택하면, 해당 시험정보에 연관된 시험일자(단건)가 시험일자 조건에 자동으로 세팅되며 수동 변경은 불가하다.
- 규칙 3: 조회 조건(지사, 시험정보, 시험일자)을 변경한 경우 조회 버튼을 다시 클릭해야 목록에 반영된다. 조건 변경만으로 목록이 자동 갱신되지 않는다.
- 규칙 4: 지사는 단일 선택만 가능하며 전체 선택은 지원하지 않는다.
- 예외 처리 1: 선택된 시험정보에 연관된 지사 또는 시험일자 정보가 없을 경우 해당 조건 영역은 공란으로 처리하고 사용자에게 안내한다.

**3. 검증 기준 (Acceptance Criteria)**

- **검증 기준 1**
    - **Given**: 사용자가 조회 조건 영역에서 지사를 선택한 상태이다.
    - **When**: 지사 선택이 완료된다.
    - **Then**: 시험선택 버튼이 활성화된다.

- **검증 기준 2**
    - **Given**: 시험선택 버튼이 활성화된 상태에서 시험정보 팝업이 표시되어 있다.
    - **When**: 사용자가 팝업에서 시험정보를 선택한다.
    - **Then**: 선택된 시험정보에 연관된 시험일자(단건)가 조회 조건 영역에 자동으로 세팅되며, 시험일자 필드는 수정 불가 상태로 표시된다.

- **검증 기준 3**
    - **Given**: 조회 결과 목록이 표시된 상태에서 사용자가 조회 조건을 변경한다.
    - **When**: 사용자가 조회 버튼을 클릭하지 않는다.
    - **Then**: 기존 조회 결과 목록은 변경되지 않고 그대로 유지된다.

**4. 데이터 요구사항**
- 입력 데이터: 시험ID (REQ-001에서 선택)
- 출력 데이터: 지사 목록 (지사코드, 지사명), 시험일자

#### REQ-003: 지사별 시행종목 목록 조회
- **우선순위**: P0

**1. 요구사항 설명**
시스템은 설정된 조회 조건(시험정보, 지사, 시험일자)에 해당하는 시행종목 내역을 조회하여 목록으로 표시해야 한다.

**2. 상세 로직 및 규칙**
- 규칙 1: 조회 버튼 클릭 시 설정된 조회 조건을 기준으로 시행종목 데이터를 조회한다.
- 규칙 2: 조회 결과는 아래 항목을 포함한 목록으로 표시한다.
  - 순번, 종목코드, 종목명, 선택분야, 선택분야명, 작업구분, 부, 시험일정공개여부
- 규칙 3: 순번은 조회 결과 기준 1번부터 순차적으로 자동 부여한다.
- 규칙 4: 조회 조건(시험정보, 지사, 시험일자)이 모두 세팅된 상태에서만 조회가 가능하다.
- 규칙 5: 조회 결과는 페이지당 20건씩 표시하며, 전체 건수와 현재 페이지 정보를 함께 표시한다.
- 규칙 6: 목록의 기본 정렬 기준은 종목코드 오름차순이며, 종목코드가 동일한 경우 부 오름차순으로 정렬한다.
- 예외 처리 1: 조회 결과가 없을 경우 목록 영역에 "조회된 데이터가 없습니다." 안내 메시지를 표시한다.
- 예외 처리 2: 필수 조회 조건 미입력 시 "조회 조건을 확인해 주세요." 유효성 검증 메시지를 표시하고 조회를 수행하지 않는다.

**3. 검증 기준 (Acceptance Criteria)**

- **검증 기준 1**
    - **Given**: 시험정보, 지사, 시험일자 조건이 모두 세팅된 상태이다.
    - **When**: 사용자가 조회 버튼을 클릭한다.
    - **Then**: 조건에 해당하는 시행종목 목록(순번, 종목코드, 종목명, 선택분야, 선택분야명, 작업구분, 부, 시험일정공개여부)이 화면에 표시된다.

- **검증 기준 2**
    - **Given**: 조회 조건에 해당하는 시행종목 데이터가 없다.
    - **When**: 사용자가 조회 버튼을 클릭한다.
    - **Then**: 목록 영역에 "조회된 데이터가 없습니다." 메시지가 표시된다.

- **검증 기준 3**
    - **Given**: 필수 조회 조건(시험정보, 지사, 시험일자) 중 하나 이상이 미설정 상태이다.
    - **When**: 사용자가 조회 버튼을 클릭한다.
    - **Then**: "조회 조건을 확인해 주세요." 메시지가 표시되고 조회는 수행되지 않는다.

**4. 데이터 요구사항**
- 입력 데이터: 시험ID, 지사코드, 시험일자
- 출력 데이터: 순번, 종목코드, 종목명, 선택분야(코드), 선택분야명, 작업구분, 부, 시험일정공개여부(Y/N)

#### REQ-004: 시행종목 조회 결과 엑셀 다운로드
- **우선순위**: P1

**1. 요구사항 설명**
시스템은 조회된 시행종목 목록을 엑셀 파일(.xlsx)로 내려받을 수 있는 기능을 제공해야 한다.

**2. 상세 로직 및 규칙**
- 규칙 1: 엑셀 다운로드 버튼은 조회 결과가 1건 이상 존재할 때 활성화된다.
- 규칙 2: 다운로드되는 엑셀 파일에는 화면에 표시된 목록 전체(순번, 종목코드, 종목명, 선택분야, 선택분야명, 작업구분, 부, 시험일정공개여부)가 포함되며, 다운로드 건수 제한은 없다.
- 규칙 3: 엑셀 파일명은 `지사별시행종목_[지사명]_[시험명]_[시험일자]_[다운로드일시].xlsx` 형식으로 자동 생성된다.
- 규칙 4: 엑셀 첫 행은 컬럼 헤더로 구성한다.
- 예외 처리 1: 조회 결과가 없는 경우 엑셀 다운로드 버튼을 비활성화하고, 클릭 시 "다운로드할 데이터가 없습니다." 안내 메시지를 표시한다.

**3. 검증 기준 (Acceptance Criteria)**

- **검증 기준 1**
    - **Given**: 시행종목 목록이 1건 이상 조회된 상태이다.
    - **When**: 사용자가 엑셀 다운로드 버튼을 클릭한다.
    - **Then**: 조회된 목록 전체가 포함된 .xlsx 파일이 자동으로 다운로드된다.

- **검증 기준 2**
    - **Given**: 엑셀 파일이 다운로드된다.
    - **When**: 파일을 열어 내용을 확인한다.
    - **Then**: 첫 행에 컬럼 헤더(순번, 종목코드, 종목명, 선택분야, 선택분야명, 작업구분, 부, 시험일정공개여부)가 표시되고, 이후 행에 조회된 데이터가 순서대로 표시된다.

- **검증 기준 3**
    - **Given**: 조회 결과가 없어 목록이 비어 있는 상태이다.
    - **When**: 사용자가 엑셀 다운로드 버튼 클릭을 시도한다.
    - **Then**: 버튼이 비활성화되어 있거나, "다운로드할 데이터가 없습니다." 안내 메시지가 표시된다.

**4. 데이터 요구사항**
- 입력 데이터: 화면에 조회된 시행종목 목록 전체
- 출력 데이터: .xlsx 파일 (순번, 종목코드, 종목명, 선택분야, 선택분야명, 작업구분, 부, 시험일정공개여부)

## 6. 사용자 인터페이스 (User Interfaces)

### 6.1 SCR-001: 지사별 시행종목 조회 화면
- **화면 유형**: 조회 (Search & List)
- **개략 설명**: 시험 운영 담당자가 조회 조건을 설정하고 해당 조건에 맞는 시행종목 목록을 조회하는 화면이다. 조회된 결과는 엑셀로 내려받을 수 있다. 화면은 ① 조회 조건 영역, ② 목록 영역으로 구성된다.
- **할당된 기능 요구사항 (Assigned Requirements)**:
    - **[REQ-001] 시험정보 선택**
    - **[REQ-002] 조회 조건 설정 (지사 및 시험일자)**
    - **[REQ-003] 지사별 시행종목 목록 조회**
    - **[REQ-004] 시행종목 조회 결과 엑셀 다운로드**
