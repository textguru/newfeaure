## 3. 빌드 대상 구성

업로드된 입력 산출물은 **도메인 코드만** 포함하고 있어, 빌드/구동을 위한 다음 자산을 추가하였다.
**업로드된 원본 Java/SQL/JSP 소스는 한 글자도 수정하지 않았다.**

### 3.1 추가된 빌드/설정 자산
| 파일 | 용도 |
|------|------|
| `pom.xml` | 의존성 및 빌드/실행 플러그인 정의 |
| `WEB-INF/web.xml` | 서블릿/필터 정의 (UTF-8 인코딩, DispatcherServlet) |
| `WEB-INF/dispatcher-servlet.xml` | 컴포넌트 스캔, MVC, 뷰 리졸버 |
| `egovframework/spring/context-datasource.xml` | 임베디드 H2 데이터소스 + 트랜잭션 |
| `egovframework/spring/context-mybatis.xml` | SqlSessionFactory / SqlSessionTemplate |
| `db/schema.sql`, `db/data.sql` | 원본 DDL 기반 H2 스키마/샘플데이터 |
| `logback.xml` | 로깅 설정 |
| `webapp/index.jsp` | 진입 리다이렉트 |

### 3.2 eGovFrame RTE 의존성 처리
- `EgovBrofClsServiceImpl` → `org.egovframe.rte.fdl.cmmn.EgovAbstractServiceImpl` 상속
- `BrofClsDAO` → `org.egovframe.rte.psl.dataaccess.EgovAbstractMapper` 상속
- 본 빌드 환경의 네트워크 정책상 eGovFrame 전용 Maven 저장소
  (`maven.egovframe.go.kr`)가 차단(HTTP 403)되어 RTE jar 다운로드 불가.
  (해당 아티팩트는 Maven Central에 미배포)
- **조치**: 동일 패키지·동일 공개 API의 경량 호환 클래스 2종을 `src/main/java`에
  추가하여 원본 소스를 무수정 상태로 컴파일/구동. 정식 eGovFrame 환경에서는
  해당 2개 파일을 삭제하고 `pom.xml`의 주석 처리된 RTE 의존성을 활성화한다.

## 6. 실행(구동) 검증 결과

`mvn jetty:run` (Jetty 9.4 + apache-jsp, 포트 8080) 으로 구동 후
전 구간(JSP → Controller → Service → DAO → MyBatis → H2)을 실제 호출 검증.

| 구분 | 엔드포인트 | 결과 |
|------|-----------|------|
| SCR-001 화면 | `GET /exam/branch-subject` | JSP 정상 렌더 (HTTP 200) |
| API-001 | `GET /brof-list` | 지사 3건 (지사명 정렬) 정상 |
| API-002 | `GET /test-info-list?brofCd=B001` | 시험 2건, T001 시행종목 집계 5건 정상 |
| API-003 | `GET /list?...&pageNo=1&pageSize=20` | 5건, 순번 부여·정렬·코드변환 정상 (H2 LIMIT 페이징 정상) |
| API-004 | `GET /excel?...` | 유효한 xlsx + 한글 파일명 헤더 정상 |
