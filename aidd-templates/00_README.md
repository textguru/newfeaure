# AIDD 입력 문서 템플릿 세트

요구사항정의서·화면설계서·화면레이아웃·프로그램설계서·테이블정의서 5종을
**로컬 LLM(Qwen 3.5 등) 기반 코드 생성 서비스**의 입력으로 쓰기 위한 표준 템플릿.

## 구성

| 파일 | 문서 | 산출 코드 영역 |
|------|------|----------------|
| `01_요구사항정의서_템플릿.md` | 요구사항정의서 | 기능 범위, 검증/예외 규칙 |
| `02_화면설계서_템플릿.md` | 화면설계서 | Controller, API 엔드포인트, 메시지 |
| `03_화면레이아웃_템플릿.md` | 화면 레이아웃 | JSP/화면 구조 |
| `04_프로그램설계서_템플릿.md` | 프로그램설계서 | Service/DAO 로직, 4계층 매핑 |
| `05_테이블정의서_템플릿.md` | 테이블정의서 | Entity/VO, DDL, MyBatis Mapper |
| `99_Qwen_생성프롬프트.md` | LLM 프롬프트 | 위 5종을 입력받아 eGovFrame 코드 생성 |

## 사용 방법

1. `01`~`05` 템플릿을 복사해 실제 과제 내용으로 채운다.
   - `{{...}}` : 치환할 값
   - `<!-- 설명 -->` : 작성 가이드(채운 뒤 삭제)
   - 표의 예시 행은 지우고 실제 행으로 대체
2. 채운 5개 문서를 `99_Qwen_생성프롬프트.md`의 사용자 프롬프트 자리에 그대로 붙인다.
3. 로컬 LLM(Qwen 3.5 등)에 시스템 프롬프트 + 사용자 프롬프트를 전달해 코드 생성.

## ID 체계 (문서 간 추적성)

문서 전반에서 아래 ID 접두어를 일관되게 사용한다. 코드 생성 시 RTM(요구사항 추적 매트릭스)으로 연결된다.

| 접두어 | 의미 | 예 |
|--------|------|-----|
| `REQ-` | 요구사항 | REQ-001 |
| `SCR-` | 화면(메인) | SCR-001 |
| `POP-` | 팝업 | POP-001 |
| `CMP-` | 화면 구성요소 | CMP-001 |
| `MSG-` | 사용자 메시지 | MSG-001 |
| `API-` | API 엔드포인트 | API-001 |
| `TBL-` | 테이블 | TBL-001 |

> **핵심 원칙**: 모든 REQ는 1개 이상의 API/화면/테이블과 연결되어야 하며,
> 모든 MSG 문구는 화면설계서와 Service 예외 메시지에서 **문자열까지 동일**해야 한다.
