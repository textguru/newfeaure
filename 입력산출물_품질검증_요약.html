입력 산출물 품질 검증 요약 — 지사별 시행종목 조회

검증일 2026-05-19 · 대상: 최종 입력 4종(요구사항 정의서 V1.0, 백엔드 API 설계서, DB 테이블 설계서, 화면 목업 HTML) · 관점: 소스코드 자동 생성 적합성

1. 문서별 품질 평가

산출물등급요지 (강점 / 코드생성 관점 한계)
요구사항 정의서 V1.0B+강점: REQ-001~004 완비, Given/When/Then 검증기준·우선순위·SCR 매핑. 한계: 비기능 요구(성능·대용량·동시성·브라우저) 전무, 순번 정의 모호, 인증 흐름 추상적, 데이터 타입은 DB문서 의존(단독 생성 불가).
백엔드 API 설계서B강점: 4개 엔드포인트 스키마·예외표·흐름도·패키지 구조 구체적. 한계: 응답 예시 JSON 문법오류(itemCount: 따옴표 누락), selectFieldName 조회 로직 미완성 스텁, 로그인/토큰 발급 API 부재, 한·중 언어 혼용.
DB 테이블 설계서B+강점: ERD·컬럼·PK/FK·인덱스·시퀀스·생성 SQL 완전. 한계: 컬럼명 오기(MAX/CURRENT_CANDINATE=응시→응원), 코드성 컬럼 허용값 미확정, 핵심 조회 복합인덱스 부재, 널 허용 복합 FK 처리 규칙 없음.
화면 목업 HTMLC+강점: 레이아웃·모달·페이지네이션·컬럼 시각 정의 명확. 한계: 지사 값 하드코딩(本部/서울)·DB 코드체계(BR001) 불일치, 시험일자 편집가능(요구사항 readonly 상충), API/상태(빈·로딩·에러)·버튼 활성상태·접근성 미표현.

2. 문서 간 정합성 이슈 (코드생성 차단·오류 유발)

이슈내용 / 영향
순번 규칙 충돌요구사항 "조회 결과 기준 1번부터 순차" ↔ 백엔드 "페이지 내 1부터". 생성 로직이 양분됨 → 단일 기준 확정 필요.
식별자 체계 불일치목업의 지사값(한자/한글) ↔ DB·API의 코드(BR001). 목업 그대로 생성 시 연동 불가 → 재작성 강제.
인증 명세 불일치요구사항은 "로그인 사용자"만, 백엔드는 401 구체화. 로그인·토큰·만료 흐름 정의 문서 부재.
추적성·언어 일관성REQ↔API↔TABLE↔SCR 매핑표 부재, 문서 내 한·중 혼용 → 산출물 일관성·검수 곤란.

3. 보완 필요 사항 (소스코드 생성 목적 기준)

순위보완 항목요청 내용
P0순번 규칙 단일화페이지 누적/페이지 내 중 1개로 확정, 요구사항·백엔드 동시 정정.
P0코드 도메인 표준화USE_YN·STATUS·WORK_TYPE·PART·EXPOSE_YN·EXAM_TYPE 허용값/코드테이블 명시 → 검증 로직 생성 가능.
P0식별자 통일 + 목업 정정지사/시험 식별자 체계 통일, 목업의 지사·시험일자 입력을 API연동·readonly로 정정.
P0API 명세 결함 수정응답 예시 JSON 문법 수정, selectFieldName 조회 로직 명세 완성.
P0인증/인가 명세 추가로그인·토큰 발급 API, 401/세션만료 처리 흐름 정의.
P1컬럼명 오기 확정*_CANDINATE → 의도(응시) 확정·정정 및 영향범위 표기.
P1비기능 요구사항응답시간·대용량 엑셀 스트리밍(SXSSF)·타임아웃·동시성·지원 브라우저 추가.
P1인덱스·무결성 보강핵심 조회 복합 인덱스(EXAM_ID,BRANCH_CODE,EXAM_DATE), 널 허용 복합 FK 처리 규칙.
P1포맷 규칙 명문화날짜·타임존, 파일명 특수문자/길이/인코딩(Content-Disposition) 규칙.
P1문서 메타·추적성작성자/검토자/승인일 기재, REQ↔API↔TABLE↔SCR 추적 매트릭스, 언어 혼용 제거.

4. 종합 결론

최종 입력물은 전반적으로 코드 생성 가능한 수준(평균 B)이며, 백엔드·DB 설계서는 거의 그대로 구현 가능했다. 다만 단독 자동 생성을 위해서는 P0 5개 항목(순번 규칙·코드 도메인·식별자 통일/목업 정정·API 결함·인증 명세) 보완이 선행되어야 한다. 이들은 검증 로직·연동·보안 코드의 정확성을 직접 좌우하므로, 미보완 시 추론에 의존한 코드가 생성되어 재작업이 발생한다(실제 1차→2차 재작업에서 REQ-002 관련 3건 보정 발생). P1 항목은 운영 품질·성능·유지보수성 확보를 위한 후속 보완 권장.
